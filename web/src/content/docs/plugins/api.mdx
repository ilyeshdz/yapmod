Every JavaScript plugin receives one frozen `api` object when `activate(api)` runs. The object is scoped to that plugin: its id, manifest, storage and settings are already resolved, and it cannot be reassigned or extended by the plugin.

```js
export default {
  activate(api) {
    // api is the only context object a plugin needs.
  },
};
```

## Module contract

`plugin.js` must use a default export:

```js
export default {
  async activate(api) {
    // Optional cleanup, returned or registered with api.onCleanup().
    return () => {
      // Runs when the plugin is disabled.
    };
  },
};
```

The module is imported as an ES module. Named exports are allowed but ignored by yapmod. There is no `deactivate` export to implement; cleanup is either the return value of `activate` or a callback registered through `api.onCleanup()`.

<Callout type="warning" title="No users or account API">
The plugin API does not expose a separate users, account or permission namespace. If the page itself makes user data available, a plugin can see it as trusted page code. Do not infer a permission boundary from the shape of this API.
</Callout>

## Errors and availability

- A method that receives an unknown setting id throws.
- An invalid storage key throws.
- Invalid CSS passed to `api.styles.add()` throws with a validation message.
- File helpers throw on a value that is not a data URI or a blob URL.
- If yapmod cannot provide an optional subsystem, some namespaces fall back to no-op implementations. For example, a missing inspector returns unsubscribe functions that do nothing, and a missing Notification API logs a warning and returns a close handle. Guard optional interface features when the app can run in a restricted webview.
- Cleanup errors are logged and recorded as a plugin diagnostic; they do not stop the remaining cleanup callbacks.

## Versioning

`api.apiVersion` is the numeric format version and is currently `1`. The manifest's `api` field must match the app's supported version. New API surfaces are introduced as new fields on the context object rather than by mutating existing signatures, so feature-detect with `api.apiVersion` or by checking for an optional namespace.
