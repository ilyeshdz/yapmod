A yapmod theme is a folder with a `manifest.json` and a stylesheet. yapmod applies the stylesheet after the app's own styles and sets two attributes on the root element so the theme can react to its own mode.

Themes are deliberately simple: **they are CSS, not JavaScript**. There is no theme runtime, no theme module and no script entry point. That makes a theme easy to audit, but it also means a theme cannot add behavior. If you need behavior, build a [plugin](/yapmod/docs/plugins).

<Callout type="note" title="Arbitrary CSS is supported">
The stylesheet is ordinary CSS. yapmod does not restrict a local theme to a fixed list of properties or selectors. The generated [token reference](/yapmod/docs/themes/styling) lists the stable colour and shape tokens you should prefer, but plain component CSS is valid too.
</Callout>

## What a theme can change

- Colours, borders, radii, shadows and spacing through **tokens** such as `--ym-bg-main` and `--ym-accent`.
- Component styling with ordinary selectors from the Yapper page.
- Light and dark variants, with a mode that can follow the app setting or the system.
- Fonts, backgrounds and other CSS features, including remote assets. See the [styling reference](/yapmod/docs/themes/styling) for the practical boundaries.

System notifications keep the operating system's look. A theme is applied to the Yapper page and the yapmod interface inside it.

## How a theme is applied

The desktop shell reads the selected theme before the page paints and sends it with the client payload. The client then:

1. Adds `data-yapmod-theme="<id>"` and `data-yapmod-mode="dark|light"` to the root element.
2. Builds a token layer that maps your `--ym-*` tokens onto the app's own variables.
3. Inserts the token layer and your stylesheet as the last stylesheet in the document, so your rules can override the app.
4. Mirrors the resolved mode into the host's own `data-theme` and `yapper-theme` state.
5. Keeps the theme applied when the system or app mode changes.

The details, including what happens with `mode: "both"` and how the host theme is restored, are in [Loading and modes](/yapmod/docs/themes/loading).

## Before you start

You need:

- A current build of yapmod, or a local build if you want to test unreleased changes.
- A text editor. No compiler, package manager or build step is needed.
- A basic understanding of CSS custom properties and selectors.

A minimal theme is two files: `manifest.json` and `theme.css`. A preview image is optional locally and recommended for the Community gallery.
